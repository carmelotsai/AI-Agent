# L4-5・索引式記憶｜學員手冊

## 日誌多了，他還找得到

> L2-3 開始，他每天寫一頁工作日誌，也會翻最近幾頁。但用了幾個月，日誌有上百頁，你問「上次跟 A 公司談價格是什麼時候？」，他只翻得到最近一週，更早的就靠運氣搜。
> 這一課幫日誌建**目錄**：每天記了哪些人、哪些公司、哪些專案，整理成一份索引；每個月再寫一份摘要。問三個月前的事，他先翻目錄，找到是哪天，再去讀那天的日誌。

---

## 這堂課結束，你會有什麼

```text
你       10:30  上次跟 A 公司談報價是什麼時候？
Melo     10:30  是 9/29 和 9/30：
                - 9/29 跟 A 公司開會，討論 B 專案的機械手臂電箱
                - 9/30 回覆 A 公司的報價單，目前還在等對方回覆
```

```text
你       10:32  九月份做了哪些事？
Melo     10:32  （照「日誌/月摘要/2026-09.md」整理：重要決定、往來的公司、產出的文件、月底還沒完成的事）
```

秘書學會：

- **查以前的事**：先查目錄，找到日期，讀那天的日誌，並告訴你是哪天的事。
- **月摘要**：每個月初自動整理上個月。

你得到：

- **`日誌/索引.md`**：主題 → 哪幾天有提到。
- **`日誌/月摘要/2026-09.md`**：一個月一份。

---

## 索引長什麼樣子

```markdown
# 主題索引

- A 公司：2026-09-29、2026-09-30、2026-10-03
- B 專案：2026-09-25、2026-09-29、2026-09-30
- 報價單：2026-09-30
- 技能：meeting-warmup：2026-10-02
```

就是一份看得懂的文字目錄。**你可以自己改**——例如把「A公司」和「A 公司」合成一條，之後他會沿用你改的名稱。

### 誰寫的

| | 誰做 |
|---|---|
| 從每份日誌列出「提到了哪些人、公司、專案、文件」 | 他 |
| 填上日期、排序、存檔 | **程式** |

日期由程式填，所以不會有「他記錯是哪天」的問題。

### 什麼時候更新

每次換日整理完工作日誌（L2-3 的流程）之後，順手更新索引。舊的日誌改過，那一天會重新整理。

升級完第一次啟動，他會把**以前所有的日誌**補整理一遍——日誌很多的話，第一次啟動會久一點。

---

## 月摘要

每個月初，他把上個月的日誌整理成一份：

```markdown
# 2026-09 月摘要

## 重要決定與結果
## 往來的人與公司
## 產出的文件
## 月底還沒完成的事
```

**「月底還沒完成的事」由程式照抄**月底最後一份日誌，不讓他改寫——測試時發現，他會把月中已經取消的事又列回來。

---

## 另一個改進：晨報改成「程式先查好資料」

這一課順便修了晨報一個問題：真機上曾經發生，晨報時他**一個工具都沒用**，直接編出一份看起來很像的晨報。

現在改成：晨報時間到，**程式先把今天的行程、提醒、重要信件、待辦、新聞都查好**，附在指令後面交給他，他只要照著寫。查不到的會照實寫「沒有連上行事曆」，不會空著讓他亂填。

這個機制寫在晨報技能的開頭（`先查:` 那幾行）。你自己寫的技能也可以用，詳見工單。

---

## 這一課他還不會的事

- **用「意思」找**：索引是用名稱找的。你說「那家做紙箱的」，他不一定知道是哪家。說出公司名最準。
- **忘記某件事**：索引和摘要是從日誌來的。想讓他忘掉，要改日誌本身。
- **檢討自己哪裡做錯**：**L4-6**。

## 上課步驟

### 步驟 1：把工單交出去

把**《L4-5_索引式記憶_施工工單.md》整份**交給 coding agent，說：

> 請照這份施工工單，幫我把秘書升級到 L4-5。

> 💾 **交工單之前**，先跟 coding agent 說「先跑 `q-backup.mjs` 檢查，再幫我存一版並備份：L4-5 升級前」。

### 步驟 2：重新上班

重新雙擊 `啟動 Agent.bat`。**第一次會比較久**：他在補整理以前所有的日誌，整理完黑視窗會印一行「主題索引：整理了 N 份日誌」（有月摘要的話還會印「已整理月摘要：…」）。等它跑完再開始用。

跑完後打開 `日誌/索引.md` 看看。

> ⚠️ 補整理會用到 API 額度：每份日誌呼叫一次模型。日誌有一百份就是一百次。免費額度每天有上限，日誌特別多、中途額度用完的話，沒整理到的那幾份會印「整理 … 的主題索引失敗，下次再試」，下次換日或重新啟動時會接著補。

## 日常管理

### 主題重複了（「A公司」「A 公司」「A 公司王經理」）

直接編輯 `日誌/索引.md`，把它們合成一條。之後他整理新日誌時會看到現有的主題名稱，盡量沿用。

### 索引太長

system prompt 只放**最近用到的 200 條**主題，太舊的不放，但檔案裡還在，他查不到時會用搜尋補。

### 想重做索引

刪掉 `日誌/索引.md` 和 `data/索引狀態.json`，重新啟動，他會全部重新整理（會用到額度）。

## 附錄・Q&A

**Q：第一次啟動跑很久？**
正常，在補整理以前的日誌。之後每天只整理一份。

**Q：他回答以前的事，但日期不對？**
看一下 `日誌/索引.md` 那個主題的日期對不對。不對的話直接改。日期是程式填的，錯的機會很小——比較可能是那天的日誌裡寫錯了。

**Q：月摘要什麼時候出現？**
每個月第一天之後第一次換日整理時。如果日誌只有這個月的，還不會有月摘要。

**Q：索引會上傳到 GitHub 嗎？**
不會。`日誌/` 本來就不進 Git（L2-7）。

**Q：晨報說「（沒有連上行事曆）」？**
程式先查行事曆時出錯了（通常是授權過期），所以照實寫。重跑 L3-5 的授權。

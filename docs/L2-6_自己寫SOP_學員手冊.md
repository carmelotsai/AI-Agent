# L2-6・自己寫 SOP｜學員手冊

## 在職訓練第六課：把你的做法教給他

> L2-4 的三本小冊子是課程附的通用做法。這一課，你要把**你自己的工作流程**寫成小冊子教給他。

---

## 這堂課結束，你會有什麼

一本**只有你的秘書會**的 SOP 小冊子。例如：

```text
你       10:05  回覆報價：客戶「大同」問 A-200 棧板機 3 台的價格，要含安裝。
Melo     10:06  報價回覆草稿整理好了（照你的報價回覆 SOP）：
                - 單價、數量、安裝費分開列
                - 交期寫「訂金入帳後 60 個工作天」
                - 結尾附上付款條件
                ⚠️ 待確認：A-200 最新單價我查不到，請提供。
                存檔：文件/2026-09-30_報價回覆_大同.md
```

黑視窗的技能清單會多出你的技能：

```text
技能：meeting-notes, quote-reply, trip-plan, weekly-report
```

---

## 什麼工作適合寫成 SOP？

| 適合 ✅ | 不適合 ❌ |
|---|---|
| **常常做**，每次做法都差不多 | 一年做一次 |
| 有**固定的成品格式**（報價單、檢查表、回覆信） | 每次都要看情況判斷、沒有標準答案 |
| 需要的資料**你會給他**，或在他的資料夾裡 | 要上網查、要讀 Word／PDF、要寄信（他還沒有這些能力） |

先想三件你最常叫秘書做的事，挑一件**做法最固定**的開始。

## 好的 SOP 長什麼樣子？

真實案例：學員請秘書「幫我建一個會議暖場的技能」，秘書自己寫出來的是這樣：

```markdown
## 步驟
1. 提供 1-2 個適合在工作會議開始前使用的冷笑話或溫馨小故事。
2. 內容需保持輕鬆、正向、適合職場。
3. 語氣簡潔、親切。
```

能用，但很單薄。每次講的笑話長度、風格可能都不一樣。比較 L2-4 的「會議紀錄」小冊子，好的 SOP 有**五個要素**：

| 要素 | 說明 | 為什麼重要 |
|---|---|---|
| **1. 封面寫清楚何時用** | 列出你平常真的會怎麼說，例如「回覆報價」「客戶問價格」 | 他靠這句判斷要不要翻小冊子 |
| **2. 步驟一步一步** | 先做什麼、再做什麼、缺資料時怎麼辦 | 少一步，他就會自己猜 |
| **3. 成品長什麼樣子** | 直接貼一份格式範本，連標題都寫出來 | 每次產出才會一致 |
| **4. 不能犯的錯** | 例如「金額不能自己估」「沒寫的填（未指定）」 | 把你最怕的事講明 |
| **5. 一個真實例子** | 「原文長這樣 → 應該寫成這樣 → 為什麼」 | **最有效的一項**。會議紀錄小冊子就是加了例子，期限判斷才從時對時錯變成 3 題全對 |

## 上課前的準備：訪談準備表

coding agent 會訪談你這些問題。**先想好答案**，最好準備一份真實的例子。

| # | 問題 | 你的答案 |
|---|---|---|
| 1 | 這件事叫什麼？ | 例：報價回覆 |
| 2 | 你平常會怎麼叫他做？（列 2～3 種說法） | 例：「回覆報價」「客戶問價格」「幫我寫報價」 |
| 3 | 他要先拿到什麼資料？資料從哪來？ | 例：客戶名稱、品項、數量；單價在 `文件/價目表.md` |
| 4 | 做法分幾步？ | |
| 5 | 成品長什麼樣子？（貼一份你以前做過的最好） | |
| 6 | 有什麼**絕對不能犯**的錯？ | 例：價格不能自己估、不能承諾交期 |
| 7 | 一個真實例子：給他什麼 → 你希望他產出什麼 | |

> 🔒 **例子裡不要放真的密碼、帳號、身分證字號**。客戶名稱、報價這類工作資料可以放。下一課（L2-7）會把小冊子備份到 GitHub 的**私人**倉庫，只有你看得到，但密碼這類東西還是不要寫進任何小冊子。

## 上課步驟

### 步驟 1：把工單交出去

把**《L2-6_自己寫SOP_施工工單.md》整份**交給 coding agent，說：

> 請照這份施工工單，幫我的秘書寫一個新技能。

### 步驟 2：接受訪談

它會問上面七個問題。把準備好的答案貼上。
如果你想做的事**超出秘書的能力**（例如要他寄信），它會告訴你，並建議縮小範圍（例如「寫好信件草稿存進 `文件/`，你自己寄」）。

### 步驟 3：看草稿、簽核

它會把寫好的小冊子**整份給你看**。重點檢查：

- 封面那句「何時用」，是不是你平常的說法？
- 成品格式是不是你要的樣子？
- 例子對不對？

確認沒問題再回「同意」。

### 步驟 4：重新上班、試用

1. 關掉舊黑視窗、重新雙擊啟動，確認「技能：」多出你的技能名稱。
2. 傳 `/new`，開一本新對話（讓他不記得剛剛在寫技能）。
3. 用你**平常的說法**叫他做那件事，看他有沒有照小冊子做。

## 進階：直接請秘書自己寫

你也可以在 Telegram 跟秘書說「幫我在 `.pi/skills/` 建一個新技能」，他會問你內容、自己寫檔。實測可行，但要注意：

- **寫完一定要重新啟動**，技能才會出現在清單上。沒重啟時他會用，只是因為記得自己剛寫過。
- **他寫的小冊子通常很單薄**（就是上面那個會議暖場的例子）。寫完用記事本打開，照「五個要素」補齊。
- **他也改得動其他小冊子**。如果你擔心他亂改，可以在 `SOUL.md` 的規矩加一條：
  > 我可以在 `.pi/skills/` 新增技能，但修改或刪除既有的技能之前，一定先問過【你的稱呼】。

建議：**第一本 SOP 照正式步驟請 coding agent 寫**，學會好小冊子長什麼樣子之後，再試試請秘書自己寫。

## 日常管理

### 繼續教他新技能

每多一件固定的工作，就多寫一本小冊子。**一本小冊子只教一件事**，不要把報價、出貨、請款全塞在同一本。

### 小冊子越用越好

他做錯的時候，別只是當場糾正，**把那次的錯誤寫成「容易搞錯的例子」加進小冊子**。下次他就不會再犯。這就是秘書的在職訓練。

### 網路上別人分享的技能能用嗎？

Pi 的技能是公開格式，網路上找得到別人寫的。**放進來之前一定要打開看過內容**：技能可以要求秘書執行指令，來路不明的小冊子，等於讓陌生人指揮你的秘書。

## 附錄・Q&A

**Q：重啟後「技能：」沒有我的技能？**
請 coding agent 執行 `node q-skills.mjs` 檢查。最常見的是缺少 `description`（那本不會載入），或名稱用了大寫、中文、空格（會警告）。技能名稱只能用**英文小寫、數字、連字號**。

**Q：他沒用我的技能，自己亂做？**
1. 你說的話跟封面「何時用」差太多 → 把你的說法加進封面。
2. 直接點名：「用報價回覆技能」。

**Q：他用了技能，但成品格式不對？**
小冊子裡的格式範本不夠具體。貼一份你心目中「標準答案」進去當例子。

**Q：可以叫他用技能寄信、查資料嗎？**
還不行。技能只能教他「怎麼做」，不能多給他新能力。寄信、查行事曆是 L3 的內容。

**Q：我寫的技能不想跟別人分享？**
小冊子是一般檔案，放在你的電腦裡。下一課備份到 GitHub 時用的是**私人**倉庫，只有你登入看得到。

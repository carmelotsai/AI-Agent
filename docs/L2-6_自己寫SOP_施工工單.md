## 0. 施工者須知

- **本課不改任何程式與設定。** 唯一的產出是 `.pi/skills/<技能名稱>/SKILL.md`（必要時加一份範例檔）。
- 你的角色是**把委託人腦中的做法，寫成 Flash-Lite 讀得懂、做得穩的 SOP**。內容一定來自訪談，不可以自己編做法。
- **先讀完整張工單，才可以動工。** 特別是 3.4 的「好 SOP 五要素」，那是本課的品質標準。
- 跟委託人說話時用**繁體中文、白話**。

## 3. 製程

### 3.1 工序一：確認 L2-5 已完工

| 項目 | 方法 | 判定 |
|---|---|---|
| 技能已啟用 | `bridge.mjs` 的 `DefaultResourceLoader` 沒有 `noSkills: true` | 有 → 請委託人先做 L2-4 |
| 緊急停止 | `bridge.mjs` 裡有 `async function stop` | 沒有 → 請委託人先做 L2-5 |
| 現有技能 | `node q-skills.mjs` | 列出現有技能，新技能名稱不可重複 |

### 3.2 工序二：訪談

一次問完以下七題。委託人答不完整的，**追問一次**；仍答不出，照紀律第 1 條處理。

| # | 題目 | 用在 SOP 的哪裡 |
|---|---|---|
| 1 | 這件事叫什麼？ | 標題、技能名稱（你幫他翻成英文名，並說明） |
| 2 | 你平常會怎麼叫秘書做？請列 2～3 種說法。 | `description` 的「何時用」 |
| 3 | 他要先拿到什麼資料？資料從哪來（你貼給他、或在哪個檔案）？ | 步驟第 1 步、缺資料時的處理 |
| 4 | 做法分幾步？每一步要注意什麼？ | 步驟 |
| 5 | 成品長什麼樣子？請貼一份你以前做過、最滿意的。 | 格式範本 |
| 6 | 有什麼**絕對不能犯**的錯？ | 規矩 |
| 7 | 一個真實例子：給他什麼 → 應該產出什麼？ | 容易搞錯的例子 |

### 3.3 工序三：能力檢查

逐步檢查訪談出來的做法，**每一步秘書都要做得到**：

| 做法需要 | 秘書做得到嗎 | 處理 |
|---|---|---|
| 讀委託人貼的文字、讀 `文件/`、`日誌/` 裡的文字檔 | ✅ | 照寫 |
| 寫檔到 `文件/` | ✅ | 照寫，檔名 `YYYY-MM-DD_主題.md` |
| 上網查資料 | ❌ | 改成「請使用者提供」或「讀 `文件/○○.md`」 |
| 讀 Word／PDF／Excel | ❌ | 請委託人另存成 `.md`／`.txt`／`.csv` 放進 `文件/` |
| 寄信、查行事曆 | ❌（L3） | 改成「草稿存進 `文件/`，使用者自己寄」 |
| 定時自動執行 | ❌（L4） | 改成「使用者叫他時才做」 |

有任何 ❌，先跟委託人說明並取得同意，再往下做。

### 3.4 工序四：草擬 SOP

照下方範本寫。**五個要素缺一不可**：

| 要素 | 檢查點 |
|---|---|
| 1. 封面寫清楚何時用 | `description` = 做什麼＋委託人的 2～3 種說法 |
| 2. 步驟 | 編號步驟；第 1 步處理「資料不夠時先問」；最後一步是回覆使用者 |
| 3. 成品格式 | 貼完整範本（標題、欄位、表格），存檔路徑寫明 |
| 4. 規矩 | 委託人第 6 題的答案，逐條寫成「不可以…」；範本預設的兩條（名稱數字照抄、沒有的不要編）保留（實測：Flash-Lite 曾把客戶「宏達」寫成「巨達（宏達）」） |
| 5. 容易搞錯的例子 | 第 7 題的例子，寫成「原文 → 正確寫法 → 為什麼」；**這是讓 Flash-Lite 穩定的關鍵**（實測：會議紀錄技能只寫規則時期限判斷時對時錯，加上一個對照例子後 3 題全對） |

**SKILL.md 範本**（`【】` 換成訪談內容）：

````markdown
---
name: 【英文技能名稱】
description: 【做什麼，一句話】。使用者說「【說法一】」「【說法二】」「【說法三】」時使用。
---

# 【技能中文名稱】

## 步驟

1. 確認已拿到：【需要的資料】。缺的一次問完，不要自己猜。
2. 【步驟】
3. 【步驟】
4. 照下方格式產出，存到 `文件/YYYY-MM-DD_【主題】.md`。
5. 回覆使用者：【回覆要包含什麼】＋存檔路徑。有不確定的地方列出來請使用者確認。

## 格式

```markdown
【委託人提供的成品範本】
```

## 容易搞錯的例子

原文：「【例子的輸入】」

| 【欄位】 | 正確寫法 | 為什麼 |
|---|---|---|
| … | … | … |

## 規矩

- 【不能犯的錯，逐條】
- 客戶名稱、人名、數字、日期照原文抄，不可以改字。
- 原文沒有的資料不要自己編，寫「（未提供）」並請使用者確認。
````

> 範例太長（超過一頁）時，可以另存成同資料夾的 `example.md`，SKILL.md 寫「參考同資料夾的 `example.md`」，做法同 L2-4 的 `trip-plan`。

### 3.5 工序五：開立《技能確認單》

把草擬好的 **SKILL.md 全文**給委託人看，並附：

```text
《技能確認單》
────────────────────────────
技能名稱：【英文名】（【中文名】）
你可以這樣叫他：【說法一】、【說法二】、【說法三】
成品會存在：文件/YYYY-MM-DD_【主題】.md
他做不到、已經調整的地方：【3.3 的處理，沒有就寫「無」】

請檢查：
  1. 叫他的說法，是不是你平常的講法？
  2. 成品格式對不對？
  3. 例子對不對？
────────────────────────────
請回覆「同意」寫入，或告訴我要改哪裡。
```

### 3.6 工序六：寫入並檢查

1. 建立 `.pi/skills/【英文名】/SKILL.md`（有範例檔一併建立）。
2. 執行 `node q-skills.mjs`，新技能必須是 ✅，而且沒有任何 ❌。

## 6. 交貨報告

1. **一句話結果**：秘書學會了「【中文名】」，你說「【說法一】」他就會照你的做法做。
2. **請他重新上班**，確認「技能：」多出新技能。
3. **品檢結果**：Q 表逐項 ✅／❌。
4. **請他做實機考核**：附 T 表。L2 總考核在下一課 L2-7（存檔與備份）做。
5. **三件要知道的事**：
   - 小冊子在 `.pi/skills/【英文名】/SKILL.md`，可以自己改，改完要重啟。
   - 他做錯時，把錯誤寫成「容易搞錯的例子」加進小冊子，下次就不會再犯。
   - 想直接請秘書寫新技能也可以，但他寫得比較單薄，寫完要打開補齊五要素，並重新啟動。

## 7. 異常處理對照表

| 現象 | 原因 | 處置 |
|---|---|---|
| 重啟後技能清單沒有新技能 | 缺 `description`，或檔名不是 `SKILL.md` | `q-skills.mjs` 檢查，補齊 |
| `q-skills.mjs` 警告 name 不合規 | 名稱有大寫、中文、空格、底線 | 資料夾與 `name` 一起改成英文小寫＋連字號 |
| 秘書不用新技能 | `description` 的說法跟委託人平常講法不同 | 把委託人實際說的話加進 `description` |
| 秘書用了技能但格式不對 | 格式範本不夠具體，或沒有例子 | 補完整範本、補「容易搞錯的例子」 |
| 秘書照 SOP 做到一半說做不到 | SOP 要求了他沒有的能力 | 回 3.3 調整做法 |
| 委託人要求加功能 | 超出本課範圍 | 照第 1 章對照表回覆 |

## 0. 施工者須知

- **本課不改任何程式，也不改 `SOUL.md`、`MEMORY.md`、技能。** 產出只有：`.git/`（版本庫）、`q-backup.mjs`（檢查腳本）、`.gitignore` 缺的行（通常不缺），以及 GitHub 上的私人倉庫。
- **GitHub 登入由委託人本人操作。** 施工者請委託人在自己開的 PowerShell 視窗執行登入指令（3.5）。不可以索取密碼、一次性代碼或權杖，也不可以代按授權。
- **這份工單可以中途重開 coding agent。** 安裝完軟體常常要重開才找得到指令。重開後從 3.1 重新檢查，已完成的步驟跳過。

- 跟委託人說話時用**繁體中文、白話**。Git 術語第一次出現時用手冊的比喻：版本相簿、存一版、雲端相簿、私人倉庫。

## 3. 製程

### 3.1 工序一：確認現況（每次重開都從這裡開始）

在**專案資料夾**（有 `bridge.mjs`、`SOUL.md` 的那一層）逐項檢查：

| 項目 | 方法 | 判定 |
|---|---|---|
| L2-6 已完工 | `node q-skills.mjs` | 有委託人自己的技能 → 繼續；沒有 → 請委託人先做 L2-6 |
| Git | `git --version` | 沒有 → 3.2 |
| GitHub CLI | `gh --version` | 沒有 → 3.2 |
| 版本庫 | `git rev-parse --show-toplevel` | 出錯（不是版本庫）→ 3.3；**是上層資料夾**（例如使用者家目錄）→ 第 7 章；就是專案資料夾 → 3.3 已做過 |
| 已連 GitHub | `git remote -v` | 有 `origin` → 問委託人這是什麼倉庫，確認後才繼續 |
| 已登入 GitHub | `gh auth status` | 已登入 → 3.5 已做過 |

把判定結果用一句話告訴委託人：「做到哪裡、接下來做什麼」。

### 3.2 工序二：安裝 Git 與 GitHub CLI

1. 告訴委託人要裝哪兩個軟體、用途（版本相簿、連 GitHub），可能跳出 Windows 權限視窗要按「是」。
2. 執行 M-01、M-02 缺的那一個或兩個。
3. 在**同一個指令**裡重新讀取 PATH 再檢查：

   ```powershell
   $env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User'); git --version; gh --version
   ```

4. 還是找不到：請委託人**關掉 coding agent，在專案資料夾重新開啟，說「繼續 L2-7 工單」**。重開後從 3.1 開始。

### 3.3 工序三：建立本機版本庫

1. `git init -b main`（3.1 判定已是版本庫的話跳過）。
2. `git config core.quotepath false`（只設在這個版本庫，讓中文檔名正常顯示）。
3. 對照 M-04 檢查 `.gitignore`，缺的行補在最後。不刪任何既有的行。
4. 在專案根目錄建立 `q-backup.mjs`（全文在 4.1）。
5. 執行 `node q-backup.mjs`。這時「還沒連上 GitHub」「有 N 個檔案改過還沒存」是 ⚠️，正常。**有任何 ❌ 先照第 7 章處理，不可以往下做。**
6. 執行 `git -c core.quotepath=false status --short --untracked-files=all`，取得「會上 GitHub」的檔案清單，給 3.4 用。

### 3.4 工序四：開立《備份確認單》

```text
《備份確認單》
────────────────────────────
倉庫：GitHub 上的「ai-secretary」，🔒 私人（只有你看得到）

會上 GitHub（共 N 個檔）：
  bridge.mjs、SOUL.md、MEMORY.md、package.json、…
  .pi/skills/ 裡的技能：meeting-notes、trip-plan、weekly-report、【委託人的技能】
  q-backup.mjs（存檔前的檢查工具）

不會上 GitHub（留在你的電腦）：
  .env（金鑰）、data/（對話存檔）、文件/、日誌/、node_modules/

存檔署名：你的 GitHub 帳號名稱＋GitHub 提供的不公開信箱（不會露出你的 Email）
【委託人已經設定過 Git 署名的話，改寫：沿用你電腦上原本的署名：名字 <信箱>】

檢查結果：q-backup.mjs 沒有 ❌，檔案裡沒有金鑰

接下來要請你：自己開一個 PowerShell 視窗登入 GitHub（我會給你一行指令）
────────────────────────────
請回覆「同意」，或告訴我哪些檔案不想放上去。
```

委託人不想放某個檔 → 把它加進 `.gitignore`（紀律第 7 條允許補行），重跑 3.3 第 5、6 步，重開確認單。

### 3.5 工序五：請委託人登入 GitHub

1. `gh auth status` 已登入 → 跳到第 4 步。
2. 請委託人：在開始按鈕按右鍵 →「終端機」，開一個**新的** PowerShell 視窗，貼上：

   ```powershell
   gh auth login --hostname github.com --git-protocol https --web
   ```

   照學員手冊步驟 4 做：問到「Authenticate Git with your GitHub credentials?」按 Enter；拿到 8 碼一次性代碼；按 Enter 開瀏覽器，登入、貼代碼、Continue、Authorize github。看到「Logged in as」後回來說「登入好了」。

   > 為什麼不由施工者執行：這個指令要在視窗裡按 Enter、看一次性代碼，施工者的終端機通常沒辦法互動；而且登入屬於委託人本人的操作。

3. 委託人說好了之後，執行 `gh auth status`，確認顯示「Logged in to github.com account 帳號」。**只看帳號名稱，輸出裡的權杖不要轉述。**
4. `gh auth setup-git`（讓 Git 推送時用 gh 的登入）。

### 3.6 工序六：署名、第一次存檔、建立私人倉庫

1. **署名**：`git config --global user.email` 有值 → 沿用，跳過。沒有值 → 告訴委託人要設定全域署名，然後：

   ```powershell
   $login = gh api user --jq .login; $id = gh api user --jq .id; git config --global user.name $login; git config --global user.email "$id+$login@users.noreply.github.com"
   ```

2. `node q-backup.mjs`：不可以有 ❌。
3. `git add -A`，再執行 `git -c core.quotepath=false status --short`：清單要跟確認單一致，**不可以有 `.env`**。
4. `git commit -m "L2-7：開始備份"`
5. 建立私人倉庫並推送：

   ```powershell
   gh repo create ai-secretary --private --source . --remote origin --push
   ```

   名稱已被用掉 → 問委託人換什麼名字（例如 `ai-secretary-2`），同一行指令換名字再執行。
6. `node q-backup.mjs`：要看到「倉庫是私人（Private）」「已備份：最新一版已經在 GitHub 上」，而且沒有 ❌。
7. `gh repo view --json url --jq .url` 取得網址，給委託人。

### 3.7 工序七：日常存檔的標準做法（示範給委託人看）

以後委託人說「先跑 `q-backup.mjs` 檢查，再幫我存一版並備份：〇〇」（學員手冊教委託人這樣說，因為以後新開的 coding agent 沒有這張工單），施工者照這個順序：

1. `node q-backup.mjs`，有 ❌ 就停下來處理。
2. `git -c core.quotepath=false status --short`，把會存的檔案告訴委託人。
3. `git add -A`、`git commit -m "〇〇"`、`git push`。
4. 回報：短版號＋說明（`git log -1 --oneline`），並說已備份到 GitHub。

委託人要退回舊版時：

1. `git log --oneline` 找到委託人說的那一版（例如「L3-1 升級前」）。
2. `git diff --stat 那一版 HEAD`，告訴委託人退回會改掉哪些檔案；工作區有還沒存的修改，先問要不要存。
3. 同意後 `git revert --no-edit 那一版..HEAD`（把那一版之後的每一版反向做一次，檔案回到那一版的樣子，歷史全部保留）。
4. `node q-backup.mjs` → `git push`。
5. 提醒委託人重新啟動秘書。

## 4. 品檢表

### 4.1 工程自檢（施工者）

| # | 項目 | 方法 | 合格標準 |
|---|---|---|---|
| Q2-7-01 | 工具 | `git --version`、`gh --version` | 兩個都有版本號 |
| Q2-7-02 | 版本庫位置 | `git rev-parse --show-toplevel` | 就是專案資料夾，不是上層 |
| Q2-7-03 | 備份檢查 | `node q-backup.mjs` | 沒有 ❌；有「倉庫是私人（Private）」「已備份」兩行 ✅ |
| Q2-7-04 | 沒碰秘書的檔案 | 回顧施工過程；`git show --stat HEAD` 對照確認單 | 只新增 `q-backup.mjs`、`.gitignore` 最多補行；沒有編輯其他檔案 |
| Q2-7-05 | 權杖沒進設定 | `git remote get-url origin` | `https://github.com/帳號/倉庫.git`，網址裡沒有 `@` |
| Q2-7-06 | 秘書照常上班 | 請委託人重新雙擊啟動 | 黑視窗跟施工前一樣，技能清單一樣 |

> 本課不改程式，**不需要**假金鑰啟動測試，也不需要建立副本。

**`q-backup.mjs`**（放在專案根目錄；只讀 Git 狀態和檔案內容，不改任何檔案、不啟動秘書，也不會印出金鑰）：

```js
// L2-7 備份檢查：只讀 Git 狀態與檔案內容，不改任何檔案、不啟動秘書、不需要金鑰。
// 用法：在專案根目錄執行 node q-backup.mjs
import { execFileSync } from "node:child_process";
import { existsSync, readFileSync, statSync } from "node:fs";
import { resolve } from "node:path";

let failed = 0;
const ok = (text) => console.log(`✅ ${text}`);
const fail = (text) => { failed++; console.log(`❌ ${text}`); };
const warn = (text) => console.log(`⚠️ ${text}`);
const run = (command, args) => {
  try {
    return execFileSync(command, args, { encoding: "utf8", stdio: ["ignore", "pipe", "ignore"] }).trim();
  } catch {
    return null;
  }
};

// 不可以進 Git 的檔案與資料夾（跟 .gitignore 必要行一致）
const REQUIRED_IGNORE = ["node_modules/", ".env", "data/", "agent.log", "文件/", "日誌/"];
const isForbidden = (path) =>
  /(^|\/)\.env$/.test(path) ||
  path === "agent.log" ||
  ["node_modules/", "data/", "文件/", "日誌/"].some((dir) => path.startsWith(dir));

// 金鑰的樣子。只報檔名和種類，絕不印出內容。
const SECRET_PATTERNS = [
  ["Gemini API Key", /AIza[0-9A-Za-z_-]{35}/],
  ["Telegram Bot Token", /\b\d{8,10}:[A-Za-z0-9_-]{35}\b/],
  ["GitHub Token", /\bgh[pousr]_[A-Za-z0-9]{36,}\b/],
  ["Google OAuth 權杖", /\bya29\.[0-9A-Za-z_-]{20,}|\b1\/\/0[0-9A-Za-z_-]{20,}/],
  ["Google OAuth 用戶端密碼", /GOCSPX-[0-9A-Za-z_-]{20,}/],
  ["填了值的金鑰欄位", /^[ \t]*(GEMINI_API_KEY|TELEGRAM_BOT_TOKEN|SERPAPI_KEY)[ \t]*=[ \t]*[A-Za-z0-9:_-]{20,}/m],
];

// 1. 工具
const gitVersion = run("git", ["--version"]);
if (!gitVersion) {
  fail("找不到 git（照工單 3.2 安裝）");
  process.exit(1);
}
ok(gitVersion);
const ghVersion = run("gh", ["--version"]);
if (ghVersion) ok(ghVersion.split("\n")[0]);
else warn("找不到 gh（照工單 3.2 安裝；只在本機存版本可以不用）");

// 2. 版本庫位置：一定要是這個專案資料夾本身，不能是上層資料夾
const top = run("git", ["rev-parse", "--show-toplevel"]);
if (!top) {
  warn("這個資料夾還不是 Git 版本庫（照工單 3.3 建立）");
  process.exit(failed ? 1 : 0);
}
const same = (a, b) => resolve(a).toLowerCase() === resolve(b).toLowerCase();
if (same(top, process.cwd())) ok("版本庫就是這個專案資料夾");
else {
  fail(`版本庫在上層資料夾 ${top}，不是這個專案（見工單異常處理）`);
  process.exit(1);
}

// 3. .gitignore 必要行
const ignoreLines = existsSync(".gitignore")
  ? readFileSync(".gitignore", "utf8").split(/\r?\n/).map((line) => line.trim())
  : [];
const missing = REQUIRED_IGNORE.filter((line) => !ignoreLines.includes(line));
if (missing.length) fail(`.gitignore 缺少：${missing.join("、")}`);
else ok(".gitignore 必要行都在");

// 4. 會進 Git 的檔案（已存的＋還沒存但沒被忽略的）
const listed = run("git", ["-c", "core.quotepath=false", "ls-files", "--cached", "--others", "--exclude-standard"]);
const files = (listed ?? "").split("\n").filter(Boolean);
const forbidden = files.filter(isForbidden);
if (forbidden.length) fail(`這些不可以進 Git：${forbidden.join("、")}`);
else ok(`會備份 ${files.length} 個檔，沒有 .env、data/、文件/、日誌/`);

// 5. 掃金鑰
const leaks = [];
for (const file of files) {
  if (file === "package-lock.json" || !existsSync(file)) continue;
  if (statSync(file).size > 1024 * 1024) continue;
  const text = readFileSync(file, "utf8");
  for (const [kind, pattern] of SECRET_PATTERNS) {
    if (pattern.test(text)) leaks.push(`${file}（${kind}）`);
  }
}
if (leaks.length) fail(`檔案裡有像金鑰的內容：${leaks.join("、")}`);
else ok("會備份的檔案裡沒有金鑰");

// 6. 歷史：以前存過的版本也不能有
const history = run("git", ["-c", "core.quotepath=false", "log", "--all", "--format=", "--name-only"]);
if (history === null) warn("還沒有存過任何一版");
else {
  const inHistory = [...new Set(history.split("\n").filter(Boolean))].filter(isForbidden);
  if (inHistory.length) fail(`以前存過的版本裡有：${inHistory.join("、")}（見工單異常處理，不要推送）`);
  else ok("歷史版本裡沒有不該存的檔");
}

// 7. GitHub
const remote = run("git", ["remote", "get-url", "origin"]);
if (!remote) {
  warn("還沒連上 GitHub（工單 3.6 之後才會有）");
} else {
  if (/\/\/[^/]*@/.test(remote)) fail("GitHub 網址裡夾帶了帳號或權杖，請改回 https://github.com/帳號/倉庫.git");
  else ok(`GitHub 倉庫：${remote}`);
  const visibility = run("gh", ["repo", "view", "--json", "visibility", "--jq", ".visibility"]);
  if (visibility === "PRIVATE") ok("倉庫是私人（Private）");
  else if (visibility) fail(`倉庫是 ${visibility}，必須改成 Private`);
  else warn("查不到倉庫是否私人（gh 還沒登入？）");
  const ahead = run("git", ["rev-list", "--count", "@{u}..HEAD"]);
  if (ahead === "0") ok("已備份：最新一版已經在 GitHub 上");
  else if (ahead) warn(`有 ${ahead} 版還沒備份到 GitHub`);
  else warn("還沒推送過（或沒有設定上游分支）");
}

// 8. 還沒存的修改（提醒，不算錯）
const dirty = run("git", ["status", "--porcelain"]);
if (dirty) warn(`有 ${dirty.split("\n").length} 個檔案改過還沒存`);

console.log(failed ? `\n有 ${failed} 項 ❌，先處理再存檔／推送。` : "\n沒有 ❌。");
process.exit(failed ? 1 : 0);
```

> 這支腳本在課程開發時的測試結果：乾淨的專案全部 ✅；`.env` 被強制加入、檔案裡藏 Telegram Token、`.env.example` 填了真值、`.gitignore` 少一行、網址夾帶權杖，都會出現 ❌；說明文件裡的中文示範值（例如 `GEMINI_API_KEY=你的Gemini金鑰`）不會誤判。

## 7. 異常處理對照表

| 現象 | 原因 | 處置 |
|---|---|---|
| `winget` 找不到 | Windows 太舊或「應用程式安裝程式」沒裝 | 請委託人到 Microsoft Store 更新「應用程式安裝程式」；或到 git-scm.com、cli.github.com 下載安裝檔，由委託人自己安裝 |
| 裝完還是找不到 `git`／`gh` | 施工者的終端機沿用舊的 PATH | 照 3.2 第 3 步重新讀取 PATH；不行就請委託人重開 coding agent |
| `git rev-parse --show-toplevel` 是上層資料夾 | 委託人家目錄或上層被人做成版本庫 | **不要動上層的版本庫。** 在專案資料夾執行 `git init -b main` 建立自己的版本庫（Git 會以最近的一層為準），再重跑 3.1 |
| `q-backup.mjs`：`.gitignore` 缺少 | 前面某一課漏加 | 照 M-04 補行，重跑 |
| `q-backup.mjs`：這些不可以進 Git（還沒存） | 被 `git add -f` 強制加入 | `git rm --cached 檔名`（只取消加入，不刪電腦上的檔），重跑 |
| `q-backup.mjs`：檔案裡有像金鑰的內容 | 金鑰寫錯地方（L1 紀律第 4 條） | 請委託人把金鑰搬回 `.env`、原檔刪掉那一行，重跑；**不可以把金鑰內容印出來確認** |
| `q-backup.mjs`：以前存過的版本裡有 `.env`，**從沒推送過** | 第一次存檔就存錯 | 這是紀律第 5 條的例外：告訴委託人要把本機的版本紀錄整個重建（檔案不受影響），同意後刪掉專案裡的 `.git/` 資料夾，從 3.3 重來 |
| **金鑰已經推上 GitHub** | 同上，而且已備份上去 | **先換金鑰**：請委託人到 Google AI Studio 刪掉那把金鑰、到 @BotFather `/revoke` 換 Bot Token、其他外洩的金鑰同樣作廢，新值填進 `.env`。換完之後舊金鑰已經沒用，倉庫是私人的，**不需要改寫 GitHub 上的歷史**；`git rm --cached .env` 後存一版推送即可。之後 `q-backup.mjs` 會一直顯示「以前存過的版本裡有 .env」，在建置紀錄記下哪幾把金鑰換過，這一項視為已處理 |
| `gh repo create` 說名稱已存在 | 委託人以前建過同名倉庫 | 不可以覆蓋或刪除。問委託人換名字 |
| `git push` 要求輸入帳號密碼 | 沒做 `gh auth setup-git` | 執行 `gh auth setup-git` 再推；不可以請委託人把密碼打給你 |
| `gh auth login` 卡在施工者的終端機 | 指令要互動 | 按 Ctrl+C 中止，改請委託人在自己的視窗執行（3.5） |
| 存檔時出現一堆 `LF will be replaced by CRLF` | Windows 換行符號提醒 | 正常，不用處理（`.gitattributes` 已處理 `.bat`） |
| 委託人要求公開倉庫 | 超出本課範圍 | 照第 1 章對照表回覆 |

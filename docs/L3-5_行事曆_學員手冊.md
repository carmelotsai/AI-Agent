# L3-5・行事曆｜學員手冊

## 授權配發第五課：看得到、也排得進你的行事曆

> 到目前為止，你問他「明天有什麼會」，他只能翻工作日誌猜。
> 這一課插上第四個外掛「行事曆」：**他直接看你的 Google 行事曆；你要他加、改、刪行程時，他先把內容傳給你確認，你按了才做。**

> ⚠️ **開始之前**：這一課會把你的行事曆內容送到 Google Gemini。用**免費層**時，Google 可能用這些內容改進產品，也可能由人工審查，[Gemini API 條款](https://ai.google.dev/gemini-api/terms)也明講不要送敏感、機密或個人資料。接公司行事曆、客戶或報價資料之前，建議先在 Google AI Studio **開啟計費、改用付費層**（L1 教的「轉正」），付費層的內容不會拿去改進產品。

## 這堂課結束，你會有什麼

```text
你       20:30  這週有什麼行程？
Melo     20:30  這週有兩個行程：
                - 9/28（一）全天：國定假日
                - 9/30（三）15:00–16:00：產品週會＠3F
                🗓️ 本次實際在 Google 行事曆：查了 2026-09-28～2026-10-04（2026-09-27）

你       20:32  下週二早上 10 點，增加與 A 公司視訊會議，一個小時
Melo     20:32  秘書要執行：calendar_create
                新增行程：
                2026-09-29（二）10:00–11:00 與 A 公司視訊會議
                [ ✅ 執行 ]  [ ❌ 不要 ]
你       20:32  （按 ✅ 執行）
Melo     20:32  好，已經幫你把「與 A 公司視訊會議」加到 Google 行事曆了。
                🗓️ 本次實際在 Google 行事曆：新增 1 筆（2026-09-27）
                🔗 https://www.google.com/calendar/event?eid=…
```

秘書學會：

- **看行事曆**：你所有「有勾選顯示」的行事曆都看得到（例如自己的、家庭的、訂閱的節日）。
- **新增、修改、刪除行程**：每一次都先傳按鈕，用白話寫清楚要做什麼；修改會寫「原本 → 改成」，刪除會加 ⚠️。你按「✅ 執行」才做。
- **做完附連結**：新增、修改完，回覆最後有這筆活動的連結，點開就能核對。
- **不打擾別人**：不會替活動加參加者，也不會寄邀請或通知給任何人。

## 怎麼知道他有沒有真的看、真的改？

跟 L3-4 查地圖一樣，回覆最後有一行**程式寫的紀錄**，AI 沒辦法假造：

```text
🗓️ 本次實際在 Google 行事曆：查了 2026-09-28～2026-10-04；新增 1 筆（2026-09-27）
🔗 https://www.google.com/calendar/event?eid=…
```

**沒有 🗓️ 這一行，就是他沒去看**（可能憑記憶或工作日誌回答），請叫他「重新查行事曆」。

## Google 設定（約 30 分鐘，一次就好）

要讓秘書碰你的行事曆，得先在 Google 那邊「開一扇門」給他。這是整個課程步驟最多的一段，但只要做一次。**請在 coding agent 照工單裝好外掛之後再做**（第 4 步要用到外掛資料夾裡的範本；見下方「上課步驟」）。

> **每一步開始前，先看畫面最上方的專案名稱是不是 `ai-secretary`。** 切錯專案是最常見的錯誤。

### 1. 建立專案

1. 用你的**個人 Gmail** 登入 [console.cloud.google.com](https://console.cloud.google.com/)。第一次用會要你同意服務條款。
2. 點最上方的專案選單 →「**新增專案**」→ 專案名稱填 `ai-secretary` →「**建立**」。
   - 如果畫面上有「帳單帳戶」「組織」欄位，照預設就好。**行事曆 API 不收費**。
3. 建立完，再點一次專案選單，**切換到 `ai-secretary`**。

> **已經有專案（例如給 n8n 用的）也請另外建一個。** 同一個專案裡的授權畫面、發布狀態、權限範圍是共用的，改了會影響另一個服務。

### 2. 啟用行事曆 API

左邊選單「**API 和服務**」→「**程式庫**」→ 搜尋 **Google Calendar API** →「**啟用**」。

### 3. 設定授權畫面

左邊選單找「**Google Auth Platform**」（或直接開 [console.cloud.google.com/auth/overview](https://console.cloud.google.com/auth/overview)）→「**開始使用**」：

| 欄位 | 填什麼 |
|---|---|
| 應用程式名稱 | `AI 秘書` |
| 使用者支援電子郵件 | 選你自己的 Gmail |
| 目標對象 | **外部**（如果有「內部」選項，不要選） |
| 聯絡資訊 | 你的 Gmail |

同意政策 →「**建立**」。

### 4. 建立你自己的隱私權政策（發布前必填）

Google 要求「正式版」應用程式要有**首頁**和**隱私權政策**兩個網址。你不用架網站，用 GitHub 免費的 **Gist**（一頁式筆記）就可以，兩個網址填同一個。

1. **用 L2-7 備份時的 GitHub 帳號**，在瀏覽器登入 [github.com](https://github.com/)。
2. **準備內容**：用記事本打開專案裡的 `外掛/行事曆/隱私權政策範本.md`（coding agent 照工單裝好外掛後才會有），把 `【填今天的日期】`、`【填你的 Email】` 換成你的，全選、複製。
   - 這個 Email 會出現在 Gist 上，填一個你願意讓別人看到的信箱。
3. **建立 Gist**：到 [gist.github.com](https://gist.github.com/)
   - 最上面的檔名欄（Filename including extension）填 `AI秘書_隱私權政策.md`
   - 下面的大框貼上剛才複製的內容
   - 按綠色的「**Create secret gist**」
4. **複製網址**：建好後，瀏覽器網址列的網址（`https://gist.github.com/你的帳號/一串英數字`）就是你的隱私權政策網址。

> **祕密（secret）還是公開（public）？** 祕密 Gist 不會被搜尋到，只有拿到網址的人看得到，Google 需要的就只是一個打得開的網址。課程實測時用的是公開 Gist；如果第 5 步用祕密 Gist 發布不成功，回來把這份 Gist 改成公開（Gist 頁面右上「Make public」）再試。

接著回 Google Cloud，左邊「**品牌**」，往下捲：

| 欄位 | 填什麼 |
|---|---|
| 應用程式首頁 | 你的 Gist 網址 |
| 應用程式隱私權政策連結 | 同一個 Gist 網址 |
| 應用程式服務條款連結 | 留空 |
| 授權網域 | 按「新增網域」→ `github.com` |

捲到最下面按「**儲存**」。

> 範本照實說明：資料只在你自己的電腦處理；你問行程時，行程內容會送到 Gemini 產生回答、經 Telegram 傳給你；新增、修改、刪除都會先問你。你自己改了程式的行為，這份政策也要跟著改。

### 5. 發布成正式版（最重要）

左邊「**目標對象**」→「發布狀態」按「**發布應用程式**」→「**確認**」，狀態要變成「**正式版**」。

> **為什麼一定要發布**：停在「測試」的話，你的授權 **7 天就會失效**，每週都要重做一次。
> 按鈕是灰的、提示「必須提供……首頁網址和隱私權政策網址」→ 回第 4 步，填完記得按儲存。

### 6. 加入權限範圍

左邊「**資料存取權**」→「**新增或移除範圍**」→ 在篩選欄搜尋、勾選這兩個 →「**更新**」：

| 範圍 | 說明 |
|---|---|
| `…/auth/calendar.readonly` | 查看日曆（看行程用） |
| `…/auth/calendar.events` | 查看及編輯所有日曆上的活動（新增、修改、刪除用） |

下方「**您預計如何使用這些範圍？**」貼這段：

```text
個人自用的 AI 秘書，只在使用者自己的電腦上執行。使用者詢問行程時讀取自己的行事曆；使用者要求時新增、修改或刪除活動，每次都會先請使用者確認。不加參加者、不寄通知，資料不提供給第三方。
```

按「**儲存**」。只勾這兩個就好，其他相似的範圍不用勾。

### 7. 下載憑證

左邊「**用戶端**」→「**建立用戶端**」→ 應用程式類型選「**電腦版應用程式**」→ 名稱隨意 →「**建立**」→「**下載 JSON**」。

在專案資料夾的 `data` 裡新增資料夾 `google`，把下載的檔案**改名成 `client.json`** 放進去：

```text
你的專案/data/google/client.json
```

> 這個檔案是你的私人憑證：**不要傳給任何人、不要貼到聊天裡**。`data/` 不會上傳到 Git，秘書也讀不到。

### 8. 授權

在**專案資料夾**打開 PowerShell（檔案總管打開專案資料夾，在網址列輸入 `powershell` 按 Enter），執行：

```powershell
node 外掛/行事曆/授權.mjs
```

瀏覽器會打開 Google 的授權頁：

1. 選你的 Gmail。
2. 看到「**Google 尚未驗證這個應用程式**」→ 點「**進階**」→「**前往 AI 秘書（不安全）**」。
   這是**你自己建的**應用程式，所以可以放心；Google 沒審查過，才會這樣提醒。
3. 勾選行事曆的權限 →「**繼續**」。
4. 瀏覽器顯示「✅ 授權完成」就好了，可以關掉那一頁。

## 這一課他還不會的事

- **邀請別人**：活動不會加參加者，也不寄邀請。要邀請請你自己在 Google 行事曆操作。
- **改整個重複活動**：每週例會這種重複活動，他只改、只刪你指定的**那一次**。
- **主動提醒你**：開會前通知你，是 L4 的事；現在請用 Google 行事曆本身的提醒。
- **看別人的行事曆**：只看得到你帳號裡有勾選顯示的行事曆。

coding agent 裝好外掛後，會請你做「Google 設定」第 1～8 步。**這一步要你本人做**：登入 GitHub、登入 Google、按同意都要你自己來，coding agent 只陪你看步驟、幫你檢查。

### 步驟 3：重新上班

**先關掉所有舊的黑視窗**，再雙擊 `啟動 Agent.bat`，然後傳 `/new`。啟動畫面：

## 日常管理

### 想收回秘書的權限

到 Google 帳戶的「[第三方應用程式和服務](https://myaccount.google.com/connections)」，找到「AI 秘書」→ 移除存取權。秘書馬上就碰不到你的行事曆了。要再用，重新做 Google 設定第 8 步。

### 授權失效了

秘書會說「Google 授權已失效…請重新執行授權」。原因可能是你收回了權限、超過 6 個月沒用，或應用程式還在「測試」狀態。重新執行一次：

```powershell
node 外掛/行事曆/授權.mjs
```

### 換電腦

`data/google/` 整個資料夾跟著專案一起搬就好；或在新電腦重新做第 7、8 步。

### 不想要這個本事

跟前幾課一樣：關掉黑視窗，把 `外掛/行事曆` 移出 `外掛/`，重新啟動。想連權限一起收回，照上面「想收回秘書的權限」做。

## 附錄・Q&A

**Q：授權時出現「已封鎖存取權：「AI 秘書」未完成 Google 驗證程序」（錯誤 403：access_denied）？**
應用程式還在「測試」狀態。做 Google 設定第 5 步發布成正式版，再重新授權。

**Q：「發布應用程式」按鈕是灰的？**
把滑鼠移到按鈕上看提示。多半是「品牌」頁還沒填首頁和隱私權政策網址（第 4 步），填完要按「儲存」。

**Q：黑視窗或秘書說「Google Calendar API has not been used in project … or it is disabled」？**
這個專案還沒啟用行事曆 API（常見原因：之前在別的專案啟用了）。確認最上方是 `ai-secretary`，做第 2 步。啟用後等 1～2 分鐘，不用重新授權。

**Q：執行授權時出現「Cannot find module …\外掛\行事曆\授權.mjs」？**
PowerShell 不在專案資料夾。照第 8 步在專案資料夾打開 PowerShell，或先輸入 `cd 你的專案路徑`。

**Q：他說「目前的 Google 授權只能看行事曆，不能修改」？**
授權時少了修改的權限（例如用舊版授權過）。確認第 6 步兩個範圍都有勾，再重新執行授權。

**Q：他新增完還說「請在畫面上按確認鈕」？**
其實已經完成了（看回覆最後的 🔗 和 🗓️ 就知道）。這多半是同一本對話裡照抄了之前的說法，傳 `/new` 就好。

**Q：黑視窗一直出現「Conflict: terminated by other getUpdates request」？**
同時開了兩個秘書（舊的黑視窗沒關）。把所有黑視窗都關掉，再開一個就好。

**Q：他說某一筆「只能看，不能修改或刪除」？**
那一筆在你訂閱的行事曆（例如節日），你本來就不能改。

**Q：改了東西沒效果？**
重新啟動。

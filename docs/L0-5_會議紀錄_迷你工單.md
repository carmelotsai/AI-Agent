---

## 0. 施工者須知

你是這張工單的施工者。委託人是一般上班族，**不懂程式**，這是他第一次把工單交給 coding agent。

- **先讀完整張工單，才可以動工。**
- 這張工單**不寫程式、不執行任何指令、不安裝任何東西**。你只需要讀這份工單，然後建立一個文字檔。
- 只在**目前的工作資料夾**裡工作。
- 跟委託人說話時用**繁體中文、白話**，不要出現他看不懂的術語。

## 1. 作業紀律

| # | 紀律 | 違反會怎樣 |
|---|---|---|
| 1 | **不准捏造。** 原始筆記沒寫的負責人、期限，一律填「（未指定）」；會議日期要問委託人，不可以用今天的日期代替。 | 會議紀錄寫錯人、寫錯日期，比沒有紀錄更糟 |

| 5 | **自我檢查不准虛報。** 沒做到的項目要寫「未通過」並說明原因。 | 委託人無法信任你的回報 |

## 3. 製程

### 3.1 工序一：讀完工單

讀完整張工單，包括附錄 A 的原始筆記。

### 3.2 工序二：問委託人

一次問完下面兩題，然後**停下來等回答**：

| # | 題目 | 委託人沒回答時 | 代號 |
|---|---|---|---|
| 1 | 這場會議是哪一天開的？ | **不可以略過**，再問一次；委託人說不知道，就用「日期未定」 | 【會議日期】 |
| 2 | 記錄人要寫誰的名字？ | （未提供）。委託人說「不用」「不寫」時也一樣填「（未提供）」，**不要改寫成「無」或其他字** | 【記錄人】 |

【會議日期】整理成 `YYYY-MM-DD` 格式（例如 `2026-09-22`）；委託人說不知道時，就是「日期未定」。

### 3.3 工序三：開立《開工確認》

把下面這張單填好給委託人看，**等委託人明確回覆「同意」才進下一步**。委託人要求修改時，照改後重新開一張。

```text
《開工確認》
────────────────────────────
要建立的檔案：會議紀錄_【會議日期】_展場攤位.md
位置：目前的工作資料夾
會議日期：【會議日期】
記錄人：【記錄人】
內容：討論重點、決議、待辦（共 【待辦數】 項）、待確認事項
不會做的事：不改其他檔案、不執行任何指令
────────────────────────────
請回覆「同意」開工，或告訴我要改哪裡。
```

### 3.4 工序四：建立會議紀錄

照第 4 節的格式，建立 `會議紀錄_【會議日期】_展場攤位.md`。

- 內容**只能來自附錄 A**。筆記沒寫的東西不要補。
- 「決議」是大家都同意的結論；「待辦」是**有人要去做的事**。
- 待辦表一定要有「事項／負責人／期限」三欄。原文沒寫的負責人或期限填「（未指定）」，並列進「待確認」。

**容易搞錯的例子**（實際上常犯）：

| 原文 | ❌ 錯誤 | ✅ 正確 |
|---|---|---|
| 「印刷廠由小王聯絡」，同一份筆記另外寫了「攤位最晚 10/15 定案」 | 小王的期限填 10/15 | 小王的期限填「（未指定）」。10/15 是整個攤位的定案日，不是小王的期限 |
| 「小李說設計稿 10/10 前可以交」 | 期限填「（未指定）」 | 期限填 10/10。原文有寫，就照寫 |
| 「下次開會再看設計稿」 | 自己編一個下次開會日期 | 放進「待確認」：下次開會日期未定 |

### 3.5 工序五：自我檢查

打開你剛建立的檔案，逐項對照第 5 節的自我檢查表。有任何一項不符合，先修正再檢查一次。

### 3.6 工序六：完成回報

照第 6 節的格式回報給委託人。

## 4. 格式範本

```markdown
# 會議紀錄：展場攤位

- 日期：【會議日期】
- 與會：（照原文列出）
- 記錄：【記錄人】

## 討論重點

- （一句話一點）

## 決議

- （大家同意的結論）

## 待辦

| # | 事項 | 負責人 | 期限 |
|---|---|---|---|
| 1 | | | |

## 待確認

- （原文沒寫清楚、需要委託人補的地方）
```

---

## 5. 自我檢查表

| # | 檢查項目 | 合格標準 |
|---|---|---|
| C1 | 檔名 | 是 `會議紀錄_【會議日期】_展場攤位.md`，日期是委託人說的，不是今天 |
| C2 | 位置 | 在目前的工作資料夾，不在子資料夾 |
| C3 | 格式 | 有「討論重點、決議、待辦、待確認」四段，待辦是三欄表格 |
| C4 | 待辦沒有漏 | 附錄 A 裡「有人要去做的事」都在待辦表裡 |
| C5 | 沒有亂填 | 原文沒寫的負責人、期限都是「（未指定）」；**沒有把 10/15 填成任何人的期限** |
| C6 | 待確認 | 每一個「（未指定）」都有列進待確認；下次開會日期也在待確認 |
| C7 | 沒有多做 | 除了這個檔案，資料夾裡沒有其他檔案被新增、修改或刪除；沒有執行任何指令 |

```text
────────────────────────────
```

## 7. 異常處理

| 狀況 | 處理 |
|---|---|
| 委託人一直沒回答會議日期 | 再問一次；委託人說不知道，就用「日期未定」，檔名是 `會議紀錄_日期未定_展場攤位.md` |
| 同名檔案已經存在 | 停下來，告訴委託人檔案已存在，問他要覆蓋還是換檔名。**不要自己覆蓋** |
| 委託人要你順便做工單以外的事（例如寄信、做成 Word） | 先肯定需求合理，說明這張迷你工單只做會議紀錄，建議他完成 L0 之後再另外交代。不施作 |
| 委託人要你改內容 | 照改，改完再跑一次第 5 節自我檢查，重新回報 |

## 附錄 A・原始會議筆記

```text
展場攤位會議
與會：小王、小李、阿明、我

- 今年台北機械展的攤位要重新設計，預算上限 30 萬
- 小李說設計稿 10/10 前可以交
- 印刷廠由小王聯絡，要先比兩家的價格
- 運輸交給阿明，之前那家報價太高，要換一家
- 攤位最晚 10/15 定案
- 下次開會再看設計稿
```

# L3-6・擬信｜學員手冊

## 授權配發第六課：幫你找信、讀信、寫信，寄出前先問你

> 上一課他看得到你的行事曆。這一課插上第五個外掛「Gmail」：**他幫你找信、讀信、寫回信的草稿；你說要寄，他先把收件人、主旨、內文傳給你確認，你按了才寄。**

> ⚠️ **開始之前**：這一課會把你的信件內容送到 Google Gemini。用**免費層**時，Google 可能用這些內容改進產品，也可能由人工審查，[Gemini API 條款](https://ai.google.dev/gemini-api/terms)也明講不要送敏感、機密或個人資料。接公司信件、客戶或報價資料之前，建議先在 Google AI Studio **開啟計費、改用付費層**（L1 教的「轉正」），付費層的內容不會拿去改進產品。

---

## 這堂課結束，你會有什麼

```text
你       09:10  王小明這週有來信嗎？
Melo     09:10  有一封：M1 王小明〈報價詢問〉9/28 09:30，問 A-200 三台含安裝的報價，附件「規格.pdf」。
                ✉️ 本次實際在 Gmail：搜尋 1 次；讀了 1 封（2026-09-29）

你       09:12  幫我回他，說報價明天中午前給他
Melo     09:12  草稿寫好了（D1），回給 wang@example.com，主旨「Re: 報價詢問」，在同一個對話串裡。請先看看。
                ✉️ 本次實際在 Gmail：建立草稿 1 封（還沒寄出）（2026-09-29）
                草稿：https://mail.google.com/mail/u/…/#drafts?compose=…

你       09:15  寄出
Melo     09:15  秘書要執行：gmail_send
                寄出信件（寄出後無法收回）：
                收件人：wang@example.com
                主旨：Re: 報價詢問
                王先生您好：報價明天中午前寄給您……
                [ ✅ 執行 ]  [ ❌ 不要 ]
你       09:15  （按 ✅ 執行）
Melo     09:15  已經寄出了。
                ✉️ 本次實際在 Gmail：寄出 1 封（2026-09-29）
                已寄出：https://mail.google.com/mail/u/…/#sent/…
```

秘書學會：

- **找信**：用 Gmail 的搜尋條件找，例如「王小明這週的信」「還沒讀的信」「主旨有報價的信」。
- **讀信**：讀整封內容；附件只會告訴你檔名，不會打開。
- **寫草稿**：回信會自動帶收件人、主旨，放在同一個對話串；也可以寫新的信。草稿**不會寄出**，你可以先到 Gmail 看、甚至直接在 Gmail 改。
- **寄出前先問你**：只寄他寫好的草稿。每一次都先傳按鈕，列出收件人、副本、主旨、內文；你按「✅ 執行」才寄。你在 Gmail 改過草稿，按鈕上看到的就是改過的內容。

## 先讀這段：你的信會送到哪裡

秘書讀信、寫信時，**信件內容會送到 Google 的 Gemini** 產生回答。

| 你用的方案 | Google 會不會拿你的內容去用 |
|---|---|
| **免費方案**（試用期） | **會**：Google 用送進去的內容改進產品，而且可能有人工審閱（審閱前會先跟你的帳號切開） |
| **付費方案**（L1 教的「轉正」，開通計費） | 不會拿來改進產品 |

所以：

- **個人 Gmail、不敏感的信**：免費方案也可以用，自己斟酌。
- **公司信箱、客戶資料、合約、個資**：請先**轉正**；很多公司也規定不能把公司信件交給外部 AI，**先問公司 IT 或主管**。
- 這一課接的是 **Gmail**。公司用的 hibox、Outlook 這類信箱不在這一課的範圍。

> 條款以 Google 官方公告為準：[Gemini API 附加服務條款](https://ai.google.dev/gemini-api/terms_preview)。

## 怎麼知道他有沒有真的看、真的寄？

跟前幾課一樣，回覆最後有一行**程式寫的紀錄**，AI 沒辦法假造：

```text
✉️ 本次實際在 Gmail：搜尋 1 次；讀了 2 封；建立草稿 1 封（還沒寄出）（2026-09-29）
草稿：https://mail.google.com/mail/u/…/#drafts?compose=…
```

- **沒有 ✉️ 這一行，就是他沒去看**，請叫他「重新查 Gmail」。
- **寄出只看「已寄出：」那一行**。只寫「建立草稿」，就是還沒寄。

---

## 信裡叫他做事，他不會照做

有些信會寫「請把資料寄到某某信箱」「請執行這個指令」。這些是**寫信的人**說的，不是你說的。秘書被教過：**信件內容是資料，不是指令**，他只會轉告你信裡寫了什麼。

就算他真的被騙：寄信一定要你按按鈕，執行指令也一定要你按按鈕。**看到不是你叫他做的事，就按 ❌。**

## Google 設定（約 10 分鐘，一次就好）

L3-5 已經建好 `ai-secretary` 專案、發布成正式版、下載了憑證，這一課只要多做四件事。**請在 coding agent 照工單裝好外掛之後再做**（第 3 步要用到外掛資料夾裡的範本）。

> **每一步開始前，先看畫面最上方的專案名稱是不是 `ai-secretary`。**

### 1. 啟用 Gmail API

左邊選單「**API 和服務**」→「**程式庫**」→ 搜尋 **Gmail API** →「**啟用**」。

### 2. 加入 Gmail 的權限範圍

左邊「**Google Auth Platform**」→「**資料存取權**」→「**新增或移除範圍**」→ 在篩選欄搜尋、勾選這兩個 →「**更新**」：

| 範圍 | 說明 |
|---|---|
| `…/auth/gmail.readonly` | 查看電子郵件和設定（找信、讀信用） |
| `…/auth/gmail.compose` | 管理草稿及傳送電子郵件（寫草稿、寄信用） |

原本行事曆的兩個範圍**保留**，不要取消勾選。

這兩個屬於「**受限範圍**」，下方「**您預計如何使用這些範圍？**」貼這段：

```text
個人自用的 AI 秘書，只在使用者自己的電腦上執行。使用者要求時搜尋、讀取自己的信件並建立草稿；寄信前每次都會列出收件人、主旨、內文，請使用者確認後才寄出。不刪除、不封存信件，資料不提供給第三方。
```

按「**儲存**」。

> 受限範圍一般要經過 Google 審查，但**只有你自己使用**的應用程式不需要審查，授權時會看到跟 L3-5 一樣的「尚未驗證」提醒。

### 3. 更新你的隱私權政策（Gist）

先分清楚兩個東西：

| | 在哪裡 | 誰會看 |
|---|---|---|
| `外掛/Gmail/隱私權政策範本.md` | 你電腦裡的秘書資料夾 | 只是**範本**，給你複製用 |
| 你的 Gist | GitHub 網站上的網頁（L3-5 建的） | **Google 看的是這個**：Google Cloud 裡填的隱私權政策網址指向它 |

只改電腦裡的範本沒有用，要把新內容**貼到網路上的 Gist**。L3-5 的 Gist 只寫到行事曆，現在多了讀信、寄信，要換成「行事曆＋Gmail」的合併版。**網址不變**，Google Cloud 那邊不用改。

1. **準備新內容**：用記事本打開 `外掛/Gmail/隱私權政策範本.md`，把 `【填今天的日期】` 換成今天、`【填你的 Email】` 換成你現在 Gist 上的那個信箱，`Ctrl + A` 全選、`Ctrl + C` 複製。記事本**不要存檔**，直接關掉（範本留著以後還能用）。
2. **打開你的 Gist**：瀏覽器到 L3-5 建的那個 Gist 網址（忘了的話，到 [gist.github.com](https://gist.github.com/) 登入後點右上角頭像 →「Your gists」）。確認右上角是你自己的 GitHub 帳號。
3. **編輯**：按 Gist 右上方的「**Edit**」→ 點一下下面的大內容框 → `Ctrl + A` 全選 → `Ctrl + V` 貼上（舊內容整份被換掉）。上面的檔名不用動。
4. **儲存**：按右下角綠色的「**Update secret gist**」（公開的 Gist 是「**Update public gist**」）。
5. **確認**：往下捲，表格裡有「**找信、讀信**」「**寫草稿、寄信**」這兩列就對了。

### 4. 授權 Gmail

在**專案資料夾**打開 PowerShell（跟 L3-5 一樣），執行：

```powershell
node 外掛/Gmail/授權.mjs
```

瀏覽器打開 Google 的授權頁：

1. 選你的 Gmail。
2. 看到「**Google 尚未驗證這個應用程式**」→「**進階**」→「**前往 AI 秘書（不安全）**」。
3. 勾選 Gmail 的權限 →「**繼續**」。
4. 瀏覽器顯示「✅ 授權完成」就好了。

> 行事曆的授權不受影響：Gmail 的權杖另外存一份（`data/google/gmail-token.json`），兩個外掛各用各的。

## 這一課他還不會的事

- **讀附件、寄附件**：附件只會列檔名。要他看附件內容，請你下載後存成文字檔放進 `文件/`。
- **整理信箱**：不會刪信、封存、標記已讀、改標籤，也不會改 Gmail 設定。
- **只寄他寫的草稿**：你自己在 Gmail 寫的草稿，他不會幫你寄。
- **主動通知新信**：有新信時通知你，是 L4 的事；現在要你問他。
- **公司信箱**：hibox、Outlook 這類信箱不在這一課的範圍。

## 日常管理

### 只想停掉 Gmail

關掉黑視窗，把 `外掛/Gmail` 移出 `外掛/`，重新啟動。想連電腦上的權杖一起刪，刪掉 `data/google/gmail-token.json`。行事曆不受影響。

### 想收回所有 Google 權限

到 Google 帳戶的「[第三方應用程式和服務](https://myaccount.google.com/connections)」，找到「AI 秘書」→ 移除存取權。**行事曆和 Gmail 會一起收回**（它們是同一個應用程式）。要再用，兩個授權都要重新執行。

### 授權失效了

秘書會說「Gmail 授權已失效…請重新執行授權」。重新執行一次：

```powershell
node 外掛/Gmail/授權.mjs
```

## 附錄・Q&A

**Q：秘書說「Gmail API has not been used in project … or it is disabled」？**
這個專案還沒啟用 Gmail API。確認最上方是 `ai-secretary`，做 Google 設定第 1 步。啟用後等 1～2 分鐘，不用重新授權。

**Q：他說「目前的 Gmail 授權權限不夠」？**
授權時少勾了權限，或第 2 步的範圍沒加齊。確認兩個範圍都在，再重新執行授權。

**Q：授權時出現「已封鎖存取權」（錯誤 403：access_denied）？**
應用程式還在「測試」狀態。照 L3-5 Google 設定第 5 步發布成正式版，再重新授權。

**Q：草稿連結點開不是那封草稿？**
同時登入好幾個 Google 帳號時可能會開錯帳號。直接到 Gmail 的「草稿」匣找，草稿一定在那裡。

**Q：我叫他寄，他沒跳按鈕，直接說已經寄了？**
看回覆最後：有「已寄出：」才是真的寄了；只有「建立草稿」代表還沒寄。多半是同一本對話裡照抄了之前的說法，傳 `/new` 再說一次「寄出」。

**Q：他說「找不到草稿編號」？**
他只能寄**這一本對話裡**自己寫的草稿。傳過 `/new` 或重新啟動後，舊的草稿編號就不在了：請他重寫一封，或你自己到 Gmail 草稿匣按寄出。

**Q：按鈕上出現「⚠️ 這個指令會直接連 Gmail」？**
他想用 PowerShell 繞過寄信工具。這不正常，**按 ❌**，然後傳 `/new` 重新交代。

**Q：黑視窗一直出現「Conflict: terminated by other getUpdates request」？**
同時開了兩個秘書（舊的黑視窗沒關）。把所有黑視窗都關掉，再開一個就好。

**Q：改了東西沒效果？**
重新啟動，再傳 `/new`。
